# RGB-D 回调耗时优化审查 — 2026-09-08

结论：存在不降低特征数量、不缩小匹配范围、不减少优化迭代的工程优化空间。优先处理**投影匹配中的重复分配/复制、ORB汉明距离内核、无界面时仍执行的显示缓存更新**。当前证据不能保证这些修改一定把所有运行的P99压到90ms以内；局部地图阶段内部尚缺细分计时，不能虚构单项毫秒收益。

本次是代码与既有数据分析，没有修改运行源码、编译或部署SLAM，也没有新增板卡回放。18轮既有测试仍是唯一运行证据。

## 优先方案：保持同样的输入、顺序、计算与判据

### 1. 投影搜索不再逐次分配并复制网格

位置：[Frame.cc](../src/Frame.cc) `GetFeaturesInArea`（约796行）、[KeyFrame.cc](../src/KeyFrame.cc)同名函数（约664行）、[ORBmatcher.cc](../src/ORBmatcher.cc)两种逐点投影匹配（约45、1683行）。

现状：每个投影地图点执行一次区域搜索。每次创建新的结果vector并 `reserve(N)`；访问每个网格时又执行 `const vector<size_t> vCell = ...`，复制整格索引。冻结库该函数确有new、memmove、delete调用，编译器没有消除这些开销。N约700时，每次结果reserve请求约5.6KB索引容量，虽通常只返回少量候选。这里是分配流量，不能当作每次新增5.6KB常驻RSS，也没有记录实际调用次数。

建议：

1. 将网格局部变量改为只读引用；网格是在帧构造/关键帧构造时填充，在该搜索过程中不修改。
2. 增加调用方提供输出vector的重载，在一次matcher调用外层准备scratch，逐地图点 `clear()` 后复用容量。保留旧接口用于其它调用方；不使用全局共享scratch。
3. 保留ix→iy→格内索引遍历顺序、层级条件、严格小于的像素边界、右目分支；输出候选序列必须逐项一致。
4. 容量根据实际N增长，不硬截断为请求的700；不得因scratch上限丢弃候选。重定位中多个存活结果或嵌套调用使用独立scratch。

这是首选：减少分配和拷贝，特征描述子、候选集与匹配顺序均无需改变。相同模式还可用于旋转直方图的30个临时vector，但其耗时未单独测量，优先级次于逐地图点调用路径。

### 2. 对32字节ORB描述子使用精确SIMD汉明距离

位置：[FeatureDescriptor.cc](../src/FeatureDescriptor.cc) `HammingDistance`（约24行）和 `FeatureDescriptorDistance`（约83行）；[ORBmatcher.cc](../src/ORBmatcher.cc) `DescriptorDistance`（约2051行）。

冻结库反汇编证明：每次距离计算先验证两个Mat并检查类型兼容性，再逐字节循环；每次循环用ldrb读取一个字节、xor后搬入向量寄存器、执行CNT与水平求和。虽然使用了CNT指令，却没有同时处理完整的16个有效字节；32字节描述子要重复32次这段循环。

可对 `CV_8UC1 && cols==32` 添加固定长度快路径，整段加载两组16字节，xor、按字节popcount、宽位水平累加。数学结果仍是同一个0–256整数，无近似距离、无浮点舍入变化。示意（尚未实施/编译）：

```cpp
uint8x16_t c0 = vcntq_u8(veorq_u8(vld1q_u8(a), vld1q_u8(b)));
uint8x16_t c1 = vcntq_u8(veorq_u8(vld1q_u8(a + 16), vld1q_u8(b + 16)));
return static_cast<int>(vaddlvq_u8(vaddq_u8(c0, c1)));
```

每个lane相加最大16，但总和最大256，必须采用返回更宽整数的累加，不能用8位水平求和导致256溢出为0。实际实现要保留尺寸/类型验证、读取边界与通用回退；浮点XFeat路径保持原样。第一步可只替换Hamming内核并保留当前验证时机。之后若细测证明Mat行对象与重复校验开销明显，再给已验证的ORB批量匹配路径使用行指针，不能直接删除公共接口验证。

必须保留候选遍历顺序、best/second更新的 `<`、比值检验、TH_LOW/TH_HIGH、旋转一致性和匹配写入顺序。距离完全一致时，这些判据无需任何调整。整数内核可以明显减少指令数量，但未测到每帧距离调用数与占用，**不能声称整个局部地图阶段会快16倍或固定省20ms**。

### 3. 地图点描述子保留锁内快照，消除32字节快照的堆分配

位置：[MapPoint.cc](../src/MapPoint.cc) `GetDescriptor`（约369行）。它持有 `mMutexFeatures` 后返回 `mDescriptor.clone()`。冻结库也直接调用Mat::clone。

建议为ORB快路径提供“复制到调用方32字节存储”的接口：在同一把锁内检查类型和宽度并复制全部字节，匹配随后使用独立快照。这样仍有一次32字节复制，但没有每个地图点一次的Mat数据堆分配。通用GetDescriptor保留原语义，避免波及浮点路径及其它模块。

不能简单改为返回 `const cv::Mat&`，也不应直接把clone改为浅拷贝后宣称线程安全：LocalMapping会更新代表描述子，浅拷贝还会改变调用方可修改的数据别名语义。即使当前写入看起来是整体替换，也应保持清晰的锁内快照边界。

### 4. 无显示消费者时，跳过显示缓存构造

位置：[Tracking.cc](../src/Tracking.cc) `Track`（约2332行）、`SearchLocalPoints`（约3711行）、`UpdateLocalMap`（约3750行）；[FrameDrawer.cc](../src/FrameDrawer.cc) `Update`（约370行）。

本次运行明确 `_enable_pangolin:=false`，但是 `Track()`仍调用 `mpFrameDrawer->Update(this)`，冻结库同样保留该调用。Update复制灰度图、关键点/深度、整个Frame的容器、投影点集合和局部地图指针，并逐匹配点更新显示统计。SearchLocalPoints另外构造逐点的 `mmProjectPoints` 映射，参考地图点也每帧复制给显示模块。

建议建立明确的“有可视化消费者”开关：该RGB-D无界面配置下跳过这些仅供显示的缓存维护；启用Viewer或外部显示消费者时保留原路径。继续保留ROS位姿/里程计/状态、地图点统计、地图保存和轨迹保存。已扫描本地消费者，mmProjectPoints主要供FrameDrawer，ReferenceMapPoints主要供MapDrawer；实施时仍须覆盖重置、地图加载及重新启用显示的情况。

此项不需要改变提取、匹配或跟踪判据。收益有上限：A_f700_r3的Track内部未细分部分在最慢5%中平均约4.00ms，包含FrameDrawer、末帧复制及其它工作，因此不能把仅跳过FrameDrawer宣称能省10–20ms。投影显示映射的构造位于local_map计时内，需另量化。

## 第二批候选：先细分测量，再做有边界的实现

### 局部地图更新的容器快照

`UpdateLocalKeyFrames()`为每个已匹配点调用GetObservations，复制一棵 `std::map<KeyFrame*, tuple<int,int>>`，实际投票只用KeyFrame指针；`UpdateLocalPoints()`为每个局部关键帧复制MapPoint指针vector。可以提供锁内填充复用vector的接口，避免复制不需要的tuple和树节点，保留快照与原map迭代顺序。

若将keyframeCounter改成排序后的连续数组，必须沿用 `std::less<KeyFrame*>`对应的键顺序、相同票数和同票时的参考帧选择；不得直接换unordered_map改变局部关键帧遍历。也不能跨帧缓存局部地图或减少更新频率：后台融合、剔除、BA会让缓存过期。这些成本可能随观测关系变化而增长，但当前CSV没有局部KF/MP数量，不能用总地图增长代替证据。

### 复用帧与灰度图存储

`mLastFrame = Frame(mCurrentFrame)`先使用自定义拷贝构造，再赋值；Frame没有显式移动操作，容器存在重复复制机会。不能仅写一个浅拷贝或移动当前帧：后续状态输出、轨迹、显示和IMU相关指针仍可能使用当前帧。应审查所有成员，提供容量可复用且保持原拷贝语义的路径，或只安全移动临时Frame；描述子所有权和IMU指针必须逐项核对。该优化也受上述未细分时间的上限约束。

`GrabImageRGBD()`每次先 `mImGray = imRGB`，再原位调用RGB→灰度cvtColor，之前的灰度缓存不会以输出缓存形式保留。可保留独立灰度输出buffer，使用相同OpenCV转换函数、相同类型和通道顺序，分辨率改变时正常重分配。不能改用近似灰度、降低尺寸或更换RGB/BGR解释。117ms灰度孤立慢帧是否会改善，当前无证据。

`System::TrackRGBD()`复制RGB/depth平均约0.6ms。只有在明确输入只读且生命周期覆盖全部消费者后才能借用原图；当前ROI、resize、颜色转换和未来IMU路径均需审查。这不是优先突破口：即使把该复制耗时算成完全免费，A_f700_r3回调P99仍约109.30ms。

### 位姿优化器的分配复用

`Optimizer::PoseOptimization()`每次创建solver、pose vertex、每个有效匹配的edge/Huber，以及多个索引vector；正常运动模型跟踪与局部地图跟踪通常分别调用。g2o每轮initializeOptimization也构造临时边集合。这里有潜力，但现有local_map计时未分开匹配和优化，不能先断言它最大。

优先复用索引工作区；若进而池化edge/solver，必须保留当前4轮、每轮请求10次迭代、误差定义、权重、Huber、离群点重入与分类、每轮初始估计行为。复用对象时重置edge level、robust kernel、顶点估计、LM求解器状态及内部ID顺序。当前g2o按internalId排序active edges，应保留该顺序和浮点累加顺序。

本地g2o的 `HyperGraph::clear()`会delete边/顶点，`setRobustKernel()`会delete旧kernel；不能简单把栈对象交给optimizer或clear后继续复用悬空指针。未经独立一致性验证，不推荐把图结构、求解器或浮点运算的重写列为第一批。

## 不符合本次“不影响质量”约束的捷径

- 减少ORB点数/金字塔层数、提高FAST门限、降分辨率、缩匹配半径、少搜地图点、少用关键帧、减少优化迭代、放松内点/重定位门限，均会改变信息或判据。
- 直接对SearchByProjection外层循环并行：候选间共享 `F.mvpMapPoints[idx]`，前面匹配会影响后面可用候选；顺序还决定距离相同时的选择。投影、距离计算可在经过冻结快照和串行提交设计后讨论，但不能把整个循环无条件OpenMP化。
- 直接开多线程ROS同时调用TrackRGBD：Tracking、Current/LastFrame和ORB workspace有顺序状态。将TrackRGBD移到工作线程可能缩短ROS接收回调指标，但不会自动减少同一帧的SLAM完成时间，必须保持计时口径。
- 删除MapPoint锁、使用旧地图快照、拖延LocalMapping/关键帧处理，都会影响一致性或地图可用时机。不能为了前台P99牺牲后台建图进度。
- 在此优化中增加fast-math、近似倒数/对数、改浮点精度或改变优化累加顺序，不满足“先保证输出一致”的路径。现有核心构建已经有O3配置，不能把打开O3作为新发现，也不能由当前缓存推断冻结库的全部编译开关。
- ORB金字塔当前逐层resize存在数据依赖，改成各层直接从原图并行resize会改变像素；ORB现有层内工作池已经复用存储并采用3 workers，不优先继续改提取链。

## 90ms目标需要多大改进

对A_f700_r3逐帧做纯算术敏感性分析，保留其它耗时不变、只按比例扣减local_map_ms，再重新计算回调分位数：

|算术情景|回调P95|回调P99|
|---|---:|---:|
|原始观测|98.71ms|109.85ms|
|局部地图阶段减少20%|88.09ms|97.78ms|
|局部地图阶段减少30%|82.70ms|93.12ms|
|局部地图阶段减少40%|77.93ms|88.15ms|
|仅ORB提取减少20%|92.38ms|103.41ms|

这不是性能预测，也不是优化后回放结果。实际提速会改变线程交错、关键帧可用时机和后续工作量。它说明P99目标需要显著的尾部收益，几项平均亚毫秒优化不能保证达标；六轮700/1/1/10即使都按局部地图减少40%作算术扣减，仍有一轮P99约90.59ms。

## 实施顺序与“不退化”的判定

建议第一批独立小改动为：网格只读引用与scratch复用 → 精确ORB SIMD距离 → 锁内描述子拷贝到固定存储 → 无界面显示缓存开关。提取链、地图选择、匹配顺序和优化器原样保留。每项独立开关/提交便于归因，不直接覆盖冻结生产。

实施前/伴随实施只需针对缺口增加有限的测量：local KF投票/MP集合、投影可见性、区域搜索、描述子比较、pose图构造/solve/分类，以及FrameDrawer/Frame复制；记录候选数、距离次数、局部点数和分配/等待相关计数。小循环以计数和批量采样为主，避免每个比较都读时钟。阶段墙钟搭配线程CPU时间，必要时调度/缺页证据，才能解释117ms灰度或百毫秒局部地图尖峰。现有fine ORB字段为零不能解释为该步骤无耗时。

“不退化”分两层，不能承诺未实施方案已通过：

1. **固定输入与地图快照的一致性**：特征坐标/层级/方向/描述子字节不变；区域候选顺序一致；Hamming含全异256、非对齐、ROI/尺寸回退等情况整数一致；best/second、匹配对、离群标记与内点数一致。若触及g2o，逐轮误差/位姿/分类要对照，不能只比较最终匹配数量。
2. **真实异步建图的质量与耗时**：相同binary baseline、参数、输入及后台工作条件，检查完整输入、相对积压、P95/P99/超90ms连续段、失跟踪/重定位、KF/MP和地图连续性，并保留LocalMapping/GBA/内存表现。异步时序变化本身可能改变地图演化，不能靠源码等价证明端到端绝对同一轨迹。当前没有真值，不能声称已证明精度不下降。

本次用户要求分析，且前轮已要求停止追加参数测试，因此上述为后续实现验收要求，**本轮没有执行这些新测试，也没有把任何优化标为已验证加速**。无需继续扫队列矩阵来确认这里已经由源码/二进制确定的开销。
