# 新诊断数据的有限原因复核

P3（1000特征、8层）在本次两轮中保留了更多有效输出，主要表现为**失跟后更多次在未触发新图或同ID重置的情况下恢复、更少进入新图或清图**，并非失跟起点减少。新增计数支持“候选和关联数量更大、最终可用内点更多”的解释；不支持“匹配保留比例更高”或“地图衰退已消除”。这些是本包、本次重复轮次的观测，不能替代位姿/深度真值验证。

分析由 [analyze_diagnostics.py](analyze_diagnostics.py) 读取封存证据生成 [DIAGNOSTIC_ANALYSIS.json](DIAGNOSTIC_ANALYSIS.json)。重点为 C_01/C_08（P0）和 C_04/C_05（P3），其余轮次仅核 BoW 日志。源码口径见 [SOURCE_INTERPRETATION.md](SOURCE_INTERPRETATION.md)。复算命令：

```
python3 artifacts/rgbd_stability_trials_20261102/analysis/analyze_diagnostics.py
```

- **C_01 P0，第60输入**：参考12→地图匹配10，局部86个关联中48个外点，剩38；正常30门槛足够，但本帧实际门槛50，仍失败。

各例原始行位于对应 `runs/<id>/board/stability/stability_frames.csv`，CSV行号为输入序号+1；JSON保留全部起点及恢复边界。此分类定位“在哪个实际判定失败”，没有据此认定模糊、遮挡、错误深度或位姿预测中的某一项为根因。

## 2. P3增加的是数量储备，保留比例没有改善

为减少输入场景不同造成的混淆，另取四轮**同时调用局部跟踪且最终OK的3878个相同原始输入序号**。以下是该条件子集每帧均值的两轮范围；不是整体收益证据，也不是对地图历史的控制实验。失败帧被条件筛掉，四轮地图、关键帧和恢复历史已经不同。

| 条件统计 | P0两轮 | P3两轮 |
| --- | ---: | ---: |
| 输入特征数 | 704 | 1005 |
| 局部点集合 | 1210–1408 | 2270–2335 |
| 实际通过视锥测试的待匹配点 | 424–485 | 866–892 |
| 局部搜索新增匹配 | 146–152 | 258–262 |
| 局部优化输入关联 | 207–210 | 339–345 |
| 局部最终内点 | 122–128 | 158–160 |
| 最终内点 / 优化输入关联（逐帧比例均值） | 57.9%–61.0% | 48.3%–48.9% |
| 最终内点 / 输入特征数 | 17.4%–18.2% | 15.7%–15.9% |
| 新增匹配 / 可见点 | 32.9%–34.7% | 33.1%–33.6% |

P3获得更多绝对内点，但同时带入更多待淘汰关联，不能写成“特征更多使匹配纯度提高”。在实际局部失跟起点，优化外点比例均值由P0的61%–66%变为P3的71%–73%；这是不同失败样本上的条件统计，不能据此断言P3造成更差几何。当前证据支持的解释是：更大的特征/关联储备提高了部分输入的成功或恢复机会，同时几何一致性和参考回退仍是限制。

前两段坐标窗口（23–100、640–710）四轮均未丢弃已产生的记录，可看到原生外点标签及边界重投影差异；后续坐标覆盖不一致，不能拿全量已存坐标混合计算“全包距离/精度改善”。`kind=2/3` 用实时地图点和边界位姿重投影，并非优化器冻结边的chi²，也没有深度真值。

P0各5128/5878帧近点数为0，P3各5114/5878帧为0，近点确实大多稀少；但近点专用条件**并非全程失效**。即使不满足近点触发，普通比例/间隔条件仍在创建KF。槽位含已有点，101不等于101个新点；特征数约增43%，后续每KF新点中位数只从74到76，不能把收益归结为每KF补点同比增加。

P3更多命中后台忙分支，且出现队列满导致本次插帧不获准的观测；队列只在原代码实际查询处记录，其余为 `NA`。这能证明存在后台接收压力，不能外推未查询帧的队列，更不能把墙钟/CPU差额叫锁等待。

生命周期全程准入聚合中，P0 found-ratio退出约4.25/4.48万、低观测龄退出4.26/4.39万；P3分别4.91/5.05万、4.64/4.77万。它们是事件计数，出生量、暴露时长和地图历史不同，不能当逐点淘汰概率。100000行寿命明细均截断；明细中的出生来源Frame ID最大仅426/445/435/264。该前缀中无KF引用的临时构造数为0，但不能推断全程没有临时点，也不能把KF引用的出生、初始化种子或所有Birth聚合当作最终存活建图点。毕业事件仅退出近期检查表，不是地图点死亡。

## 4. “点更多、内点更少”仍在，不能一概当持续衰退

采用可复算的探索性端点比较：每个已知map-ID/reset分段内，只取实际局部调用、结束Frame仍有效的记录；至少30次调用时比较前10与后10的中位数，另在至少40次调用的分段用第11–20次作敏感性对照。

| 分段端点同时出现“局部点增、内点减” | C_01 P0 | C_08 P0 | C_04 P3 | C_05 P3 |
| --- | ---: | ---: | ---: | ---: |
| 前10 vs 后10 | 24/24 | 29/30 | 15/16 | 13/14 |
| 第11–20 vs 后10 | 22/24 | 29/30 | 13/15 | 14/14 |

这说明P3没有消除该现象；但不是每帧单调下降，也不是地图点年龄导致衰退的因果证明。端点接近失跟天然更容易观察到低内点，还存在场景变化和地图选择偏差。初始化本帧没有实际局部内点测量，绝不能把约700/1000个种子点写成同数量内点。

例如C_01 P0分段23，前10次局部点中位数554、内点121.5，末10次变为2061.5、63；去掉最初10次后，内点仍从119降到63。反例是C_04 P3最长分段11：前10次内点195.5、末10次102.5，看似衰退；但第11–20次已降到95.5，末尾反而略高。因此一部分“启动高、随后低”确有初始化附近瞬态成分。

**P3另有2组/3组合图日志，无法定位到确切输入时点，也未验证合图正确性。** 因而P3这些epoch只隔开已知map-ID变化和同ID清图，不能称为完全隔离、始终未改变的单图历史。局部集合增大可能包含合图搬迁；KF集合加入/移除也不是唯一创建：P3记录的KF add为1239/1300、erase为74/85，不能替代前台创建帧数。这里没有把合图后的更长有效输出当作合图正确性的证明。

## 5. BoW修复针对参考回退，不能解释全部初始几何损失

专门BoW ABBA对照保持诊断开启：两个OFF轮各发现1次、4次空参考BoW；两个ON轮均0。OFF事件的精确输入序号为1437，以及319/674/1706/1729。全部参考粗匹配失败日志与逐帧计数按数量、顺序和值完整匹配后才关联源序号；日志行和KF ID保存在JSON。

这5次均是 OK→RECENTLY_LOST：先有运动模型优化后的地图匹配3–9<10，再进入参考回退，参考BoW为空、当前帧BoW非空、匹配为0，局部跟踪未执行。空参考BoW直接解释回退路径为何不能提供有效词袋匹配；**它没有解释此前运动模型为什么只留下3–9个地图匹配**。eager移除的是已确认的发布前就绪缺口及恢复能力放大因素，不是全部失跟的统一根因。

8个矩阵轮次均开启eager，空参考日志也均为0；但仍有非空词袋下的粗匹配失败和大量优化后不足10的失败。日志只在粗匹配<10时打印空标记，“未出现空日志”不是对所有读取或所有数据竞争的全覆盖审计。原关闭模式含未同步访问风险，小样本事件次数也会随时序变化，不能据5→0分配整体收益比例。

## 证据限制与下一步

四轮坐标均达到262144行上限；P0第5窗口部分截断、第6完全缺失，C_04 P3第3窗口已截断、之后均缺失，C_05 P3第4窗口部分截断、之后均缺失。完整逐帧计数仍可定位后段失败阶段，但后段具体投影/深度形态未知。全部寿命明细截断，原因聚合继续累计。`complete=true`只表示刷盘成功，`workers_joined=false`仍保留，不能宣称后台任务全部完成。

下一步应先对现有原图中上述代表失败帧及成功邻帧做对照，把“匹配不足”和“优化大量剔除”分开；在当前已封存数据无法支持时，明确保留未知。若后续另行授权观测实验，优先给后段窗口单独预算并记录精确合图身份/边界，再考虑距离分桶和持续点队列，而不是直接把所有远点、65535或ThDepth当成已知错误来源。当前数据尚不能证明深度准确性，也不能证明合图或轨迹准确性；降低30/50阈值可能增加错误接受，本复核不据这些计数建议放宽门槛。
