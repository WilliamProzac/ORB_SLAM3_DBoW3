# LM01 实测后的条件后续方案（尚未实现）

完成 C6 后，KF 硬上限、事务隔离和恢复机制的功能测试通过，但板端实时性和输入完整性失败；MP=5000/6500/8000 在这些轮次均未触发截断。不能把局部点数量减少当成实时性收益，也不能把影子集合召回高当成轨迹质量通过。

## 优先定位事务和汇集成本

先使用已经记录的 gather、snapshot、commit、锁等待和 Local BA CPU/墙钟时间，区分扫描、对象同步、后台计算和线程等待。以同构建 off 为基线，单独测完整事务路径；保持特征、匹配阈值和队列不变。C6 长包 B 的 snapshot/commit P95 已达数十毫秒，MP 截断不绑定，优先处理这一固定成本。

先把细粒度生命周期日志开/关列为独立同构建对照，保留基本输入/回调计时，区分日志与锁交互开销。本轮正式 A/B 共同开启该日志，未单独量化开关成本；C2 在没有该日志时也未达标，不能假定关闭日志即可通过。整进程 CPU 与回调相对时钟缺少共同起点，若要精确关联，新增明确时钟锚点再采样，不能事后强行对齐。

第一项小改动候选是把 KF 投票使用的观测关系从反复分配的 `std::map` 快照改为复用连续容器，聚合后恢复原来的确定性遍历/同分顺序。它必须重新通过旧完整路径兼容、丢弃尝试等价、竞争关联、并发和板端 A/B。不能以强所有权为理由移除锁，也不能通过取消完整重试降低报表耗时。

## 查询在前的外观索引

作者的 [MIH 论文](https://arxiv.org/abs/1905.07797) 用当前外观约束局部地图；[GF-ORB-SLAM2 项目](https://github.com/ivalab/gf_orb_slam2) 同时提供外观索引、特征匹配预算和 BA 子图选择。它们是后续算法参考，不是当前 RDK 收益的证据。

2026-09-24 核对的 [Tracking.cc](https://github.com/ivalab/gf_orb_slam2/blob/catkin/src/Tracking.cc#L3506) 中，`Combined` 分支先遍历共视 KF 的地图点槽位，再和哈希结果求交；`HashOnly` 走另一条路径。仅移植求交部分，不能省掉本次已测得的前置汇集扫描。下载源码 SHA256：`9a170cb7b5b952557148b1250cb024f05a36ea52e94371acd9e5102c2af11e1b`。

建议另立实施阶段：

1. 先实现只读查询诊断，按运行代次和 MP ID 标识条目，索引持有弱句柄；出生、描述子更新、替换、退休、地图转移分别处理失效。查询结果取得强句柄后仍需受同步保护的快照与验证。
2. 在 KF 槽位扫描前取得候选，保留入口已有匹配、上游禁止重搜语义和安全 KF 支持。限制查询桶访问、返回数量及维护成本，全部计时；不能先扫描全图再称作有界检索。
3. 先影子冻结名单，复用本轮的新增匹配/实际关联召回、几何、统计机会和出生批次诊断，再开放一次完整回退。索引维护内存和锁等待计入整机指标。
4. 通过原定输入、精度、回环和 P95/P99 门槛后再考虑启用；索引生命周期或一致性失败时保持关闭。

## 单独评估预算化 Local BA

本轮已经观察到大量 Local BA 中断和秒级墙钟长尾。是否首先限制 BA，应以新增 CPU 计时判断；不能把全部等待都当作优化器计算。C6 长包 B 的 BA CPU P95 为 759～1338 ms，墙钟 P95 为 829～1392 ms，但 Local BA 调用线程合计只占整进程 CPU 约 6.8%～7.5%，其余建点/剔除/回环等成本需分别定位。旧计时列 lba_map_points 未赋值，使用独立 MemoryStats 的候选点数及实际图顶点/边数，避免拿零值拟合费用模型。

[Good Graph 论文](https://arxiv.org/abs/2008.10123) 研究在计算预算内选择条件性较好的 BA 子图。后续可以据此设计独立阶段，保持完整全局地图：

1. 用 RDK 的边数、优化/固定 KF 数、MP 数、完成/中断、CPU/墙钟分布拟合费用模型，同时记录模型误差；不要照搬桌面时间预算。
2. 影子选择 BA 子图，明确当前 KF、锚点、固定边界、足够几何约束及地图事件处理。先比较图条件性、选择开销和预测费用，不改变求解。
3. 独立接入有界子图并保留现有取消、写回和生命周期契约；不以删除地图对象或修改剔除阈值代替子图选择。
4. 使用相同 S316、闭环、TUM 和保存重载矩阵。验收仍是前端回调、输入完整性、轨迹和回环的联合门槛；BA 完成率提高本身不构成准入。

这些后续阶段不包含在本次已经提交的 LM01 算法实现中。当前负面结果及完整回退能力必须保留，不能据论文的其他平台结果宣称 RDK 已达标。
